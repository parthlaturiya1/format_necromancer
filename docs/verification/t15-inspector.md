## N1 first: the grey header (answer: a UI bug, not an engine gap)
The engine does report header evidence. For `rings-rand-111x111.pcx` the analysis evidence of the winning hypothesis holds `header-block` (bytes 0 to 128), `size-numbers`, `row-stride`, `body`, `table-tail`, `run pairs`, `table records` and more. The old `indexFromRecovered` read only the recovery evidence (one record per row), so nothing coloured bytes 0 to 127. Fix: `src/ui/regions.ts` builds one region list from both. Analysis regions are coloured by their confidence (same thresholds as the engine config). An analysis range that wraps whole rows (the body) is marked "umbrella": it can be picked from the list but never colours bytes, so it cannot hide an uncertain row. Unit tests: header bytes read as explained, the byte answer picks the tightest region, umbrella never wins.
